# Contributing to Wardkeeper

## Branches

Create a branch from the latest `main` for each change. Name it:

`type/name/description-or-issue-tag`

Use lowercase words separated by hyphens. `name` is the contributor's GitHub username or real name. Choose a type that describes the work: `feat`, `fix`, `docs`, `design`, `test`, or `chore`.

Examples:

* `feat/nadif/room-booking`
* `docs/bilal/issue-42`
* `fix/omar/overlapping-bookings`

## Pull requests

Do not push directly to `main`. Push your branch and open a pull request targeting `main`. A short description can help when the change has not already been discussed with the team, but it is optional.

Any contributor with write access may merge a pull request, including their own, once GitHub allows it. A teammate's review can be useful, but approval is not required. Use a merge commit so the branch's individual commits remain in the history. Delete the branch after merging.

Do not commit sensitive or private material to the repository.
